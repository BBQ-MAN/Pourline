2. 곡선·자연 형태: 각진 카드 대신 둥근 블롭·물방울. 채워지는 컵·물결로 진행을 보인다.

## 0. 핵심 긴장과 해법

D6("값 변화에 애니메이션 없음")과 D2(숫자 흔들림 금지)는 사용자 방향 1과 정면으로 부딪친다. 숫자를 스프링으로 보간하면 표시가 실제보다 늦고(과다 추출), 목표 근처에서 실제보다 큰 값을 보일 수 있다. 그래서 화면을 두 겹으로 나눈다.

| 겹 | 대상 | 규칙 |
|----|------|------|
| 숫자 겹 | 무게·타이머·유량 숫자, 단계 카드 글자, 배너, 칩 | 지금 명세 그대로. 받은 프레임에 바로 그린다. 보간·외삽·트윈 없음. tnum + 고정 폭 끝 정렬 |
| 모양 겹 | 차오르는 물, 수면 물결, 리본 굵기, 물방울 머리, 블롭 윤곽, 장식 물방울 | 숫자 겹이 이미 보인 값을 뒤따른다. 오버슈트 0인 임계 감쇠 스프링(4.1 `motion.follow`), 정상 램프 지연 52 ms 이하. 정보는 숫자 겹에 모두 있고, 모양 겹은 같은 정보를 반복할 뿐이다 |

이 해법은 D6 문장을 바꿔야 한다(12절 결정 1). 제안 문구: "D6. 숫자 겹(무게·타이머·유량 숫자, 단계 글자)은 받은 프레임에 바로 그린다. 모양 겹은 오버슈트 없이 숫자 겹을 따르고, 지연은 램프 기준 60 ms 이하다. 모양 겹만으로 전달되는 정보는 없다."

## 1. 디자인 원칙

1. **움직임은 물의 양이다.** 모든 움직임은 저울 값(무게·유량)이나 상태 변화에서 나온다. 데이터가 멈추면 화면도 멈춘다. 시간만으로 도는 대기 애니메이션(숨쉬는 배경, 떠다니는 블롭)은 없다. ECC `frontend-design-direction`이 경고하는 "장식용 블롭"을 피하는 규칙이고, 배터리와 주의력도 아낀다.
2. **숫자가 먼저, 모양은 뒤에.** 숫자 겹은 지연 0. 모양 겹은 숫자를 앞지르지 않는다(외삽 금지, 오버슈트 금지).
3. **곡선은 데이터를 담는다.** 곡률·두께·높이가 바뀌면 그것은 무게·유량·단계를 뜻한다. 의미 없는 변형 진폭은 반지름의 2.5%(약 4 dp) 이하로 묶는다.
4. **움직임 없이도 다 읽힌다.** "애니메이션 삭제"를 켜도 정보가 하나도 사라지지 않는다. 멈춘 값(D11)은 움직임이 멈추는 것만으로 알리지 않고 색·점선·글자로 알린다.
5. **한 화면, 한 은유.** 한 시안 안에서 은유(서버·리본·물방울) 하나만 주인공이다. 다른 화면은 같은 모양 토큰만 이어 쓰고 새 은유를 더하지 않는다(ECC `taste`: 일관성이 새로움을 이긴다).

|------|------|------|------|

| `extraLarge` | 28 dp | 32 dp | 시트 위 모서리, 대화상자 |
| `AppShape.pill`(추가) | — | `RoundedCornerShape(percent = 50)` | S1 동작 줄 버튼(64 dp 높이 → 반지름 32 dp), 주 버튼, 세그먼트 버튼 바깥 |

겹친 모서리(ECC `make-interfaces-feel-better` 동심 반지름): 바깥 = 안 + 여백. 카드 28 dp − 여백 16 dp = 안쪽 요소 12 dp(`small`). 배너 20 dp − 여백 12 dp ≈ 8 dp지만 배너 안 `TextButton`은 pill로 둔다(여백 12 dp 이상 = 별도 면, ui-design 6.4 규칙 그대로).

### 2.2 블롭 경로 규칙

- 기본형: 둥근 사각형 또는 초타원(Compose `androidx.graphics.shapes.RoundedPolygon` + `CornerRounding(radius, smoothing = 1f)`, 또는 직접 만든 `Path`).
- 변형: 기본 윤곽을 각도로 72점 표본화하고 각 점을 바깥 법선 방향으로 δ(θ)만큼 민다. δ(θ) = A·(sin(3θ + φ) + 0.5·sin(5θ − 1.3φ)). A와 φ는 유량에서만 나온다(4.3). 랜덤·노이즈 금지(결정적 스크린샷을 위해).
- 경로: 72점을 Catmull-Rom → 3차 베지어(제어점 = Pᵢ ± (Pᵢ₊₁ − Pᵢ₋₁)/6)로 잇는 닫힌 곡선. 모서리 없음(G1 연속).
- 최소 곡률 반지름 8 dp. 진폭 A 최대 4 dp(반지름의 2.5% 이하).
- 블롭 안의 글자 상자는 블롭의 가장 안쪽 윤곽(A 최대일 때)에서 16 dp 이상 떨어진다. 윤곽이 글자에 닿지 않는다.

### 2.3 물방울 경로(`AppShape.drop`)

단위 상자 100 × 140(끝이 위). SVG·Compose `Path` 공통:

```
M 50 0 C 50 0, 92 58, 92 92 C 92 118, 73 140, 50 140 C 27 140, 8 118, 8 92 C 8 58, 50 0, 50 0 Z
```

- 크기 토큰: `drop.s` 10 × 14 dp(단계 표식), `drop.m` 14 × 20 dp(리본 머리), `drop.l` 24 × 34 dp(빈 상태 그림).
- 회전: 끝이 움직임 반대쪽(꼬리)을 향하게 회전한다. 리본 머리는 접선 각도 + 180°.
- 상태: 속 빈 물방울(테두리 1.5 dp `onSurfaceVariant`) = 아직, 채운 물방울(`tertiary`) = 도달. 색과 채움을 함께 바꾼다(색만으로 구분하지 않음, D4·D7 원리).

### 2.4 서버(용기) 경로(`AppShape.vessel`, 시안 A)

단위 상자 100 × 100, 위가 열린 둥근 서버:

```
M 11 0 L 89 0 C 95 18, 100 42, 100 61 C 100 83, 79 100, 50 100 C 21 100, 0 83, 0 61 C 0 42, 5 18, 11 0 Z
```

- 채움 가능 높이: 바닥(y 100)에서 위 여유 8%(y 8)까지. 수면 y = 100 − 92·h, h = 무게 ÷ 물 목표(레시피 물 g). h는 0~1.08로 자른다(목표를 넘으면 위 여유까지 찬다).

## 4. 모션 토큰

### 4.1 스프링·트윈 토큰

Compose `spring(dampingRatio, stiffness)`는 질량 1이다. HyperFrames(JS)에서는 같은 값으로 k = stiffness, c = 2·ζ·√k를 쓴다(4.4 코드).

| 토큰 | Compose | JS k / c | 성질 | 쓰는 곳 |
|------|---------|----------|------|---------|
| `motion.follow` | `spring(dampingRatio = 1f, stiffness = Spring.StiffnessMedium /*1500f*/)` | 1500 / 77.46 | 임계 감쇠, 오버슈트 0. 램프 지연 2/ω = 52 ms. 계단 2% 정착 150 ms | 수면 높이, 리본 끝·물방울 머리 위치, 블롭 안 액체 높이 |
| `motion.calm` | `spring(1f, Spring.StiffnessLow /*200f*/)` | 200 / 28.28 | 임계 감쇠. 2% 정착 412 ms | 물결 진폭·물결 속도, 블롭 일렁임 진폭, 물줄기 굵기 |
| `motion.slosh` | `spring(0.35f, 60f)` | 60 / 5.42 | 약 1.2 Hz로 출렁이다 0.85 s 안에 10% 아래로 잦아듦 | 붓기를 멈출 때 수면 기울기(시안 A·C) |
| `motion.drop` | `spring(0.6f, Spring.StiffnessMediumLow /*400f*/)` | 400 / 24.0 | 오버슈트 약 9.5%(장식이라 허용) | 단계 물방울 채움 scale 0.6 → 1, 영점 표식 등장 |

### 4.2 10 Hz 데이터를 매끄럽게 잇는 규칙

입력 사실: 0x01은 평균 100 ms(간격 2~243 ms, C-01-12), 무게 0.1 g, 유량은 저울이 낸 직전 1 s 순증가(0~99.9 g/s, C-01-5·C-01-7)를 엔진이 다시 1 s 평균한 값(architecture 7.2).

1. **숫자 겹**: 표본이 도착한 프레임에 그대로 그린다. 보간·외삽 없음.
2. **모양 겹 목표값**: 가장 최근 표본. 매 표본마다 `motion.follow`로 목표를 바꾼다. 진행 중인 속도를 이어받는다(Compose `Animatable.animateTo`를 새 코루틴으로 다시 부르면 이전 애니메이션이 취소되고 속도가 이어진다. 또는 화면에 프레임 루프 하나를 두고 직접 적분한다).
3. **외삽 금지**: "마지막 값 + 유량 × 경과"로 앞질러 그리지 않는다. 목표 근처에서 실제보다 많은 물을 보이게 된다.
4. **오버슈트 금지**: 값을 담는 모양(수면, 리본 끝, 액체)은 dampingRatio 1만 쓴다.
5. **큰 점프는 순간 이동**: 한 표본에서 50 g 넘게 바뀌면(컵 올림·내림, 99.9 g/s 튐) `snapTo`. 스프링으로 화면을 가로질러 쓸지 않는다. 음수 무게는 액체 높이 0으로 자른다.
6. **곡선 경로**: 그래프·리본 중심선은 표본을 지나는 단조 3차 보간(Fritsch–Carlson)으로 그린다. 이웃 표본보다 높거나 낮은 가짜 봉우리를 만들지 않는다. 값 없는 구간(끊김·과부하)은 선을 끊는다(ui-design 4.4 그대로). 경로는 새 표본이 올 때만(10 Hz) 다시 만들고, 프레임마다 바뀌는 것은 머리 위치뿐이다.
7. **유량에서 나온 움직임**: 물결 진폭·속도, 물줄기 굵기, 블롭 일렁임은 화면 유량 값을 `motion.calm`으로 한 번 더 거른 값 f로 만든다. 유량 숫자는 그대로 보인다.
8. **표본이 멈추면 모양도 멈춘다**: `NoData`·끊김·과부하에서는 모양 겹이 마지막 표본에 정착한 뒤 멈춘다. 물결 진폭은 `motion.calm`으로 0이 된다. 그 뒤 D11 표시(3.1 멈춘 값 색·점선 + 무게 아래 줄 글자)를 바로 건다.
9. **프레임 루프 범위**: 모양 겹 프레임 루프는 phase가 `WaitingForPour`·`Running`이고 화면이 `RESUMED`일 때만 돈다. `Idle`·`Paused`·`Finished`와 백그라운드에서는 정지(마지막 상태로 그대로 그림).

### 4.3 유량 → 움직임 공식(시안 공통)

f = `motion.calm`으로 거른 화면 유량(g/s).

| 값 | 공식 | 예(f = 9.0 / 4.0 / 0) |
|----|------|------------------------|

### 4.4 HyperFrames용 스프링 적분(JS)

```js
// 임계·부족 감쇠 공통. dt = 1/60 s를 4번 나눠 적분(안정·정확)
function springStep(s, target, k, zeta, dt) {
  const c = 2 * zeta * Math.sqrt(k), h = dt / 4;
  for (let i = 0; i < 4; i++) { const a = -k * (s.x - target) - c * s.v; s.v += a * h; s.x += s.v * h; }
}
// motion.follow: springStep(level, latestSample, 1500, 1.0, 1/60)
// motion.calm:   springStep(fState, shownFlow, 200, 1.0, 1/60)
```

### 4.5 모션 줄이기(Reduce motion)

판단: `Settings.Global.ANIMATOR_DURATION_SCALE == 0f`(접근성 "애니메이션 삭제"가 켜는 값). `ContentObserver`로 바뀜을 받는다. Compose 기본 애니메이션은 `MotionDurationScale`을 따르지만, 직접 만든 프레임 루프(물결 위상)는 따르지 않으므로 이 값을 명시적으로 확인한다.

| 요소 | 기본 | 모션 줄이기 |
|------|------|-------------|
| 숫자 겹 | 즉시 | 즉시(같음) |
| 수면·리본 끝·액체 높이 | `motion.follow` | `snapTo`. 10 Hz 계단으로 바로 바뀜 |
| 물결·블롭 일렁임·출렁임 | 유량 비례 | 없음. 수면은 평평한 직선, 블롭은 기본형 |
| 물줄기 | 굵기가 유량 따라 바뀜 | f ≥ 0.3이면 3 dp 고정 굵기로 보이고 아니면 숨김(움직임 없음) |
| 단계 물방울 채움 | `motion.drop` scale | 즉시 채움 |
| 목표 수위선 이동 | `motion.target` | 즉시 이동 |
| 떨어지는 물방울·물결 고리 | 있음 | 없음 |
| 카드 색 숨 | `motion.tint` | 없음 |
| 완료 블롭 가라앉기 | `motion.settle` | 즉시 최종 모양 |
| 화면 전환 | fade 200/150 | 시스템이 0으로 줄임(즉시) |

애니메이션 배율 0.5×·2×는 Compose가 스프링 경과 시간을 그 배율로 늘이고 줄인다. 직접 만든 루프도 같은 배율을 곱한다.

### 6.4 합성 추출 데이터(V60 기본 15 g / 250 g)

레시피(architecture 8.3): 1단계 "뜸 60 g, 30초 기다리기 (95°C, 중간-가는 분쇄)" 누적 60 g @ 0:10, 2단계 "0:40 나머지 물을 작은 원으로 천천히 250 g까지" 누적 250 g @ 1:30. 끝 시각 = 마지막 단계 90 s. 자동 완료 = 90 s 뒤 무게가 5 s 동안 0.5 g 넘게 바뀌지 않음 → t 95.0 s.

생성 규칙(결정적, 100 ms 표본 k = t × 10). 유량은 프로토콜 규칙(C-01-7)으로 무게에서 계산하고, 화면 유량은 엔진 1 s 평균(architecture 7.2)이다.

```js
const TAU = 2 * Math.PI;
function w(t) {                       // g, 앱 타이머 t초
  if (t < 0) return 0;
  if (t <= 10) { const x = t / 10; return 61 * (x - 0.5 * Math.sin(TAU * x) / TAU); }       // 뜸 붓기, 61 g에서 멈춤(1 g 넘게 부음)
  if (t <= 40) return 61;                                                                       // 뜸 기다림
  if (t <= 90) { const x = (t - 40) / 50;                                                      // 2차 붓기, 원 그리며 8번 출렁
    return 61 + 189 * (x - 0.5 * Math.sin(TAU * x) / TAU - 0.3 * Math.sin(8 * TAU * x) / (8 * TAU)); }
  return 250;
}
const raw = k => Math.round(w(k / 10) * 10);                              // 0.1 g 정수(저울 raw)
const scaleFlow = k => Math.min(Math.max(raw(k) - raw(k - 10), 0), 999); // 직전 1 s 순증가, 0~999
const shownFlow = k => { let s = 0; for (let j = k - 9; j <= k; j++) s += scaleFlow(j); return s / 100; }; // g/s, 화면 값
// 표시: 무게 (raw(k)/10).toFixed(1), 유량 shownFlow(k).toFixed(1)
```

### 7.2 장면

**① 대기·영점(0.0–3.0 s)**

**② 붓기 중(3.0–10.0 s, t 0 → 7)**

**③ 단계 전환(10.0–14.0 s, t 7 → 11)**

### 7.4 Compose 구현

- `Canvas` + `drawWithCache`로 서버 `Path`(단위 경로를 크기에 맞춰 `Matrix` 변환) 캐시. 액체: `clipPath(vesselPath)` 안에서 물결 `Path`(4 dp 간격 점) 채움.

- 난이도: 중(5점 중 3). 새 의존성 없음.

- t 10 → 11: 유량이 잦아들며 새 표본의 리본 굵기가 10 → 3.8 dp로 가늘어져 리본이 붓기 끝에서 가늘게 꼬리를 남긴다. 머리 꼬리 길이도 줄어 둥근 물방울이 된다(`motion.calm`).

**④ 목표 도달·완료**
- 14.0 s 하드 컷: 리본은 이미 0~86 s 전체가 그려져 있다. 뜸 구간(굵음) → 기다림(2.5 dp 가는 수평) → 2차 붓기(원 붓기로 2.5~8 dp 사이 8번 부풂). 이 굵기 리듬이 "붓는 방식"의 흔적이다.
- 14.0–18.0 s: 머리가 (86 s, 241.3 g) → (90 s, 250 g)로 흐름. 굵기 4.3~5.3 dp.
- t 90.0(18.0 s): 250 g 꼭짓점 물방울 채움 `motion.drop`.
- 18.0–19.0 s(5×): 리본이 2.5 dp 수평으로 5 s만큼(14.6 dp) 이어짐.
- 19.0 s 자동 완료: 머리 물방울이 꼬리를 거둬 지름 12 dp 원이 되고(`motion.settle`, 약 500 ms), 그 자리에서 물결 고리(반지름 0 → 28 dp, 2 dp `#6F4A2E`, `motion.ripple`).
- 19.90 s → S6: 리본 그래프 정지 스냅숏(같은 스타일, 328 × 240 dp).

### 8.4 Compose 구현

- 기존 `BrewChart` `Canvas` 확장. 리본: 표본마다 중심선 점과 법선 방향 ±굵기/2 점을 이어 닫힌 `Path` 하나(위쪽 가장자리 → 아래쪽 가장자리 역순)로 채운다. 급한 꺾임은 단조 보간이라 적고, 끝은 반원.
- 경로는 새 표본 때만 갱신(최대 36 000점, 화면 픽셀 폭보다 촘촘하면 1 dp당 1점으로 솎는다). 머리는 `Animatable<Offset>`(`Offset.VectorConverter`) + `motion.follow`.
- 물방울: 단위 `Path`를 `rotate`·`translate`로 그림.
- 난이도: 중상(5점 중 3.5). 굵기 리본 경로와 솎기가 핵심. 새 의존성 없음.

### 9.2 장면

**① 대기·영점**
- 0.0 s: 블롭 기본형, 액체 없음, 일렁임 0.
- 1.16 s: 무게 즉시 `0.0`. 블롭이 한 번 숨 쉰다: 기본형 크기 scale 1 → 1.015 → 1(가로 약 5 dp, `motion.drop` 0.6/400, 약 500 ms). 기준점은 블롭 가운데. 숫자 상자는 움직이지 않는다(블롭 `graphicsLayer`만 크기 변화).

**② 붓기 중(t 0 → 7)**
- 액체가 블롭 바닥부터 찬다(`motion.follow`). t 7에서 h = 0.189 → 수면 y ≈ 322. 아직 숫자 아래.
- 수면 물결 A_w(4.3), 파장 72 dp, 블롭 폭이라 약 4.5 마루가 보임. 수면선 `#6F4A2E` 2.5 dp.
- 블롭 윤곽 일렁임: 2.2절 δ(θ), A_b = min(4, 0.45·f) dp → t 5~7에서 4 dp, 위상 속도 0.56 Hz(f = 9). 숫자 상자와 윤곽 거리 16 dp 이상 유지.
- 물줄기 없음(블롭 위에 입구가 없다). 대신 수면 가운데에 유량 비례 작은 물결 원(시안 A와 같은 규칙).

**③ 단계 전환(t 7 → 11)**
- t 9.7: 카드 글자 즉시. 블롭 바닥 가운데(x 180, y 360)에서 물방울 하나(`drop.m`, `#6F4A2E`, 끝이 위)가 떨어져 나와 카드 위쪽 가장자리(y 456)까지 `motion.fall` 320 ms로 떨어지고, 닿으면 카드 위 가장자리에 물결 고리(가로 타원 반지름 0 → 32 dp, `motion.ripple`) + 카드 색 숨 `motion.tint`. 물방울은 장식이라 글자 바뀜을 기다리지 않는다(글자는 t 9.7에 이미 바뀜).
- t 10 → 11: 일렁임 A_b·물결 A_w → 0(`motion.calm`). 수면 출렁임 `motion.slosh`.

**④ 목표 도달·완료**
- 14.0 s 하드 컷: h = 0.965 → 수면 y ≈ 167. 숫자 전체가 액체 안에 있다(숫자 `#211A16` on `#FFDCC4` 13.31:1). 일렁임 A_b 0.9~1.4 dp.
- t 90.0: 수면이 채움 위 끝(y 160)에 닿음. 미니 그래프 250 g 꼭짓점 물방울 채움.
- 18.0–19.0 s(5×): 잔잔해짐.
- 19.0 s 자동 완료: 블롭이 일렁임 0의 고른 모양으로 가라앉고, 모서리 반지름 96 → 110 dp(더 둥글게)로 `motion.settle`(약 600 ms, `androidx.graphics.shapes.Morph` 또는 반지름 보간). 블롭 바깥으로 물결 고리 1개(블롭 윤곽에서 24 dp 바깥까지 퍼지며 알파 0.6 → 0, `motion.ripple`).
- 19.90 s → S6: 다 찬 블롭 정지 그림(숫자 "250.0 g"는 S6 지표 칸이 맡으므로 그림 안에는 숫자 없음).

### 9.4 Compose 구현

- `Box` 안에 뒤 `Canvas`(블롭·액체·물결) + 앞 `WeightReadout`(지금 컴포넌트 그대로). 블롭 크기는 `WeightReadout` 측정 높이에서 정한다(`Layout` 또는 `SubcomposeLayout`).
- 블롭 경로: 프레임마다 72점 Catmull-Rom `Path`(A_b > 0일 때만 다시 만들고 0이면 캐시). 완료 모양 바꿈은 `androidx.graphics:graphics-shapes`의 `RoundedPolygon`·`Morph`(새 의존성, 버전은 구현 전에 공식 문서로 확인) 또는 둥근 사각형 반지름 `Animatable` 보간(의존성 없음, 권장).
- 액체·물결은 시안 A와 같은 코드(`clipPath`).
- 난이도: 상(5점 중 4). 숫자와 그림의 겹 배치, 글꼴 배율에 따른 블롭 크기, 대비 스크린샷 검증 상태 수가 늘어난다.
