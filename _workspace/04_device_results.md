## B1 첫 실행 권한 허용 → 스캔 → 연결 (2026-11-03 00:35)

- 권한: 새로 설치한 상태(BLUETOOTH_SCAN·CONNECT granted=false)에서 사용자가 허용 → 둘 다 granted=true, USER_SET.

- **A-1 (Android API) 확정:** `getManufacturerSpecificData(0xFFFF)`가 2바이트 `01 01`(화이트리스트 방송, DOT)을 준다.
- 새 관찰: Android에서는 화이트리스트 방송(`01`)에도 이름 `TIMEMORE_Dot`이 붙어 있었다(macOS 프로브 A에서는 일반 방송에만 이름). 앱은 이름으로 거르지 않으므로 영향 없음.
- 연결 직후 읽기: 단위 `00`(g), 배터리 `03 64`(100%), 타이머 `03`(리셋) — 모두 응답 받음(190~250 ms).
- 0x01 무게 알림: 556프레임 / 55.4 s = **10.04 Hz**. 배터리 Notify 30 s 간격(+23.1 s, +53.1 s).
- 무게: +28.8 s에 0 → 최대 298.0 g까지 올라갔다가 약 1 s 안에 0.0 g으로 돌아옴. (사용자 확인 대기: 올린 물건과 저울 화면 값)

- 크래시 없음.
- 판정: 연결 부분 **통과**. "무게 표시가 저울 표시와 같음"은 사용자 확인 후 확정.

## B4 로그(04_device_b_B4.log)에서 나온 관찰 — 영점 시험 전

- +71.15 s 물건(47.7 g)을 올리자 2샘플(3.5 g, 44.5 g) 뒤 +71.28 s에 앱이 `SetTimer(Start)`를 보냈다(자동 시작). 이 로그 구간에는 Pourline의 영점(`TX A55A030D…`)이 없다. 자동 시작 무장은 영점 성공 뒤에만 되므로(architecture 7.2), B1 로그를 멈춘 뒤 이 로그를 시작하기 전 사이에 영점을 눌렀을 가능성이 있다(사용자 확인 대기). 영점을 누르지 않았는데 자동 시작됐다면 버그다.
- **저울은 두 앱의 동시 연결을 받는다.** +192 s부터 공식 TIMEMORE 앱이 붙자, 그 앱의 읽기 응답(opcode 02 cmd 08·18·0C·13·04, 03 06, 03 0D)이 Pourline에도 FFF1 알림으로 왔다. Pourline은 모르는 cmd를 `버림 Unknown`으로 버렸다(크래시 없음). 다만 아는 cmd의 응답(02 02 타이머 읽기, 02 05 배터리, 03 0D 영점)도 다른 앱 것이 섞여 들어온다. Pourline이 영점을 보낸 직후 다른 앱의 영점 응답이 오면 자기 응답으로 받을 수 있다. 공식 앱의 영점(+204.2 s 응답)도 저울에 그대로 적용됐다. → 결정 필요 항목: 다른 앱이 같은 저울에 붙어 있으면 안내할지.
- 처음 보는 프레임: 02 08 `0201`, 02 18 `01`, 02 13 `544553303137`("TES017", 모델명), 02 04 `0100000000`, 03 06 `01`. 공식 앱이 보낸 명령의 응답이며 원문에 없는 cmd(0x08·0x18·0x13)가 있다.
- 사용자 확인: B1과 B4 사이에 Pourline 영점을 눌렀다 → 위 자동 시작은 설계대로(영점 → 0 g로 무장 → 물건 올림 2샘플).
